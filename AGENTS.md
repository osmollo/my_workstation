# AGENTS.md

## Scope
- This repo is an Ansible workstation bootstrap repo, not an app/library project. The primary entrypoints are `install.yml`, `post_install.yml`, `work.yml`, and focused playbooks under `playbooks/`.
- Playbooks target `localhost` with `connection: local`; changes often affect the real machine state, not a sandbox.

## Runtime Wiring
- `ansible.cfg` is part of the runtime contract: custom modules live in `./library`, shared helpers in `./module_utils`, and lookup plugins in `./lookup_plugins`. Do not move or rename these paths casually.
- Distribution and desktop-specific behavior is resolved by `playbooks/load_distro_vars.yml`; many roles expect `linux_distribution` and `desktop_environment` facts from that playbook.

## Main Commands
- Base install: `ansible-playbook install.yml`
- Post-install personal config: `ansible-playbook playbooks/prepare_post.yml && ansible-playbook post_install.yml`
- Work config: `ansible-playbook playbooks/prepare_post.yml && ansible-playbook work.yml`
- Focused extra software install uses tags, not separate playbooks: `ansible-playbook install.yml -t "vscode,dropbox,spotify"`
- Disable system package updates for a run with `REPO_DISABLE_UPDATES=1` or `-e disable_updates=true`

## Secrets And Generated Files
- `post_install.yml` fails unless `roles/post_install/defaults/main.yml` exists; `work.yml` fails unless `roles/work/defaults/main.yml` exists. Those files are generated by decrypting the checked-in `.gpg` files via `playbooks/prepare_post.yml`.
- `post_install.yml` and `work.yml` also require a working 1Password session; `playbooks/check_op.yml` asserts both `OP_SESSION_*` in the environment and `op account get` succeeding.
- `roles/post_install/defaults/main.yml` is gitignored; treat it as generated secret material and avoid editing or committing it unintentionally.

## Verification
- There is no repo-local lint/test wrapper. The safest verification is a focused `ansible-playbook` run against the smallest relevant entrypoint or tag.
- For changes inside a role task file, prefer tag-scoped checks first, for example `ansible-playbook install.yml -t ssh_config` or `ansible-playbook post_install.yml -t git`.
- `install.yml` runs package updates unless disabled and may change `.git/config` plus `~/.ssh/config`; avoid broad runs when a tag-scoped run will verify the change.

## Repo Structure
- `roles/common`: OS/bootstrap packages, update flow, shells, SSH client, distro/desktop-specific vars.
- `roles/extra_software`: third-party app installation split by category; install toggles live in `roles/extra_software/defaults/main.yml` as `install_*` booleans.
- `roles/post_install`: personal machine/user configuration after bootstrap.
- `roles/work`: work-specific machine/user configuration and repo cloning.
- `playbooks/`: utility entrypoints such as `load_distro_vars.yml`, `prepare_post.yml`, `update_packages.yml`, `restore_desktop_config.yml`, and `delete_repos.yml`.

## Gotchas
- Debian-family runs can fail early unless the user has sudo rights; `playbooks/load_distro_vars.yml` explicitly tells the user to run `playbooks/debian_sudo.yml` and re-login when needed.
- Update skipping is stateful: `roles/common/tasks/main.yml` uses `/var/tmp/.update` and a 1-week age check, so package-update behavior can differ between runs even with identical commands.
